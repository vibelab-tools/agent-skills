# 面向初学者的 OAuth 2.0

现代 Web 安全离不开两个概念：身份认证和权限控制。OAuth 2.0 主要解决的是后者，也就是“一个应用能访问用户的哪些资源”。你平时点击“使用 Google 登录”时，背后通常就有 OAuth 在工作。

先区分两个容易混淆的概念。认证是确认“你是谁”，授权则是决定“你能访问什么”。OAuth 2.0 属于授权机制。它允许第三方应用访问用户的资源，比如邮箱或日历，同时不需要拿到用户密码。

OAuth 2.0 里有四个角色：

- 资源所有者，也就是用户；
- 客户端，也就是请求访问权限的应用；
- 授权服务器，负责验证用户并签发令牌；
- 资源服务器，保存受保护的数据。

最常见的流程是授权码模式。客户端先把用户重定向到授权服务器，用户在那里登录并同意授权。授权服务器随后把一个授权码发送到客户端指定的回调地址。客户端再拿这个授权码和自己的客户端密钥，向授权服务器换取访问令牌。拿到访问令牌后，客户端就可以向资源服务器请求相应资源。

访问令牌通常有效期较短，常见情况是一个小时左右。访问令牌过期后，客户端可以使用刷新令牌获取新的访问令牌，这样用户不必重新确认授权。

对于单页应用，浏览器里不适合保存客户端密钥。PKCE（Proof Key for Code Exchange）扩展可以在授权码流程中增加一层保护，并避免客户端密钥必须存放在浏览器里。

掌握 OAuth 2.0，不需要一开始就记住所有细节。先把这几个角色、令牌和授权码流程弄清楚，你就有了理解现代 API 安全的基础。
